# ADR 0008: one formatting pipeline, gated in CI

- **Status:** Proposed
- **Date:** 2026-09-10
- **Related Artefacts:**
    - Amends: [AGENTS.md](../../AGENTS.md) (Formatting section, which named nixfmt-tree as the whole of the record)
    - Answers: #219
    - Constrains: [treefmt.toml](../../treefmt.toml), [.markdownlint-cli2.yaml](../../.markdownlint-cli2.yaml), [.prettierrc.yaml](../../.prettierrc.yaml), `formatter` in [flake.nix](../../flake.nix)

## Context

Formatting was three pipelines that disagreed: the editor (conform.nvim over LazyVim defaults plus a local markdownlint wrapper), the harness (opencode's per-language commands over PATH binaries), and CI (`nix fmt -- --ci` over nixfmt-tree, Nix only). Markdown took the worst of it - prettier and markdownlint-cli2 reformat each other's output forever over list indentation, and no gate noticed because CI never looked at Markdown. AI-agent diffs arrived with formatting churn mixed into content changes, which is what #219 measured: the churn is incomprehensible precisely where review needs to be mechanical.

## Decision

There is one pipeline, `nix fmt`, defined by ./treefmt.toml and executed with binaries from the nixpkgs pinned in flake.lock:

- The editor's formatter set (conform.nvim + LazyVim) is authoritative for what runs on each file type; the pipeline mirrors it rather than inventing a second set.
- Where the pipeline cannot follow the editor - files whose established format is structurally hostile to a formatter, or that are deliberately adversarial test input - the file is excluded from the pipeline and the editor is configured to skip it too, so neither side "fixes" what the other will not check.
- Versions are a property of flake.lock, not of anyone's PATH. A contributor's newer formatter reformatting files CI then rejects is the failure this closes.
- Markdown converges by construction: the two Markdown formatters agree by configuration rather than by re-editing each other's output, and lint rules the repo's established formats structurally violate are scoped off with a recorded reason - ADRs are append-only and templates are load-bearing, so neither can be retrofitted.
- Harnesses delegate: opencode formats through `nix fmt -- <file>` rather than per-language commands, and the AFK runner's implement prompt tells the session to run `nix fmt` (write mode) before committing, so formatting lands in the ticket's commits and the `--ci` gate stays a pure check.

The parameters that implement these decisions - which formatters exist and in what order they run, which paths are excluded, the Markdown overrides that stop the two Markdown formatters fighting, and which lint rules are scoped off - live in ./treefmt.toml, .prettierrc.yaml and .markdownlint-cli2.yaml, each exception carrying its reason beside it. Reversing one is a text-editing change, not a reversal of this decision.

## Consequences

**Positive**

- `nix fmt -- --ci` green means every formatter agrees; a red gate names a file, not a style debate.
- Editor, harness and CI consume the same binaries and configs, so the class of diff that motivated this - formatting churn inside content changes - has nowhere left to come from.

**Negative**

- Prettier and markdownlint-cli2 versions now move with flake.lock bumps. An upstream prettier change that reflows Markdown lands as a tree-wide style commit, not as one file at a time.
- Hugo layouts and the garden fixture are outside every formatter. Their consistency is the garden VM check and human preview, not the gate.

## Alternatives considered

- **Per-language check steps in ci.yml with no unification.** Keeps three pipelines and the drift between them; rejects nothing the editor would not reintroduce on the next save.
- **A `style` commit generated by automation (#219 item 2's idea, and its CI-pushed variant).** #219 pictured the AFK harness reformatting the whole repo into a separate `style` commit before the PR opens; the CI-pushed variant of the same idea writes to the contributor's branch from a workflow run, which needs `contents: write` on the path the AFK denylist exists to keep read-only. Both rejected: the churn still lands in the PR, merely quarantined into one commit, and the mechanism hides a formatting failure behind a bulk commit instead of letting the session's own commits pass the gate. The agent runs `nix fmt` (write mode) before its ordinary commits instead; the `style` commit this PR carries is the one-time normalisation of the existing tree, not the ongoing mechanism.
- **Remove the editor and harness formatting controls entirely (the option #219 item 5 asks to consider).** Rejected: the failure was divergence between the controls, not their existence - the editor's format-on-save is wanted behaviour, so the fix was consolidation, every remaining control delegating to the one pipeline, rather than removal.
- **Pre-commit hooks.** Unenforceable on agent worktrees and unattended runs; a gate the author can skip is documentation, not a control.
