# Quickshell shell survey

A survey of design patterns in the popular Quickshell desktop shells, for designing a small vertical-bar, motion-free Quickshell shell for Hyprland. Surveyed 2026-11-27. Versions read: Quickshell v0.3.2 plus master at [`9b0f339b`](https://github.com/quickshell-mirror/quickshell/tree/9b0f339b19057f4731bf3b48293307d7ef241671) (2026-10-21; nixpkgs ships 0.3.2); Caelestia shell at [`3605357e`](https://github.com/caelestia-dots/shell/tree/3605357e1e3d48346943509153c000e3facf4126) (2026-11-25, latest release v2.5.0); DMS, now _Dux Modular Shell_, at [`2cb19fb4`](https://github.com/duxlabs-dev/dux-shell/tree/2cb19fb439c8b3146198a8cec3aae8cc75646938) (2026-11-26, shell `v2.2-beta`, latest release v2.1.2); end-4 dots-hyprland at [`21733c3c`](https://github.com/end-4/dots-hyprland/tree/21733c3ca7f4edc20faafedea844dc96002c6f7f) (2026-11-15); Noctalia at [`54958562`](https://github.com/noctalia-dev/noctalia/tree/54958562e9f8a83aaa07eba7c0ff353ba45b1167) (2026-11-27, v5.6.0).

Two changes since mid-2026 affect how to read everything below:

- **Noctalia is no longer a Quickshell shell.** v5, stable since v5.0.1 on 2026-09-03, is "a native C++ and OpenGL ES shell". The Quickshell-based v4 line survives on the `legacy-v4` branch ([FAQ](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/getting-started/faq.mdx), [SCOPE.md](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/SCOPE.md)). The repo has also been renamed from `noctalia-shell` to `noctalia`. Its _design_ is still worth reading, so it stays in this survey, but its _code_ tells you nothing about Quickshell. I found no statement from the authors explaining why they left Qt.
- **DankMaterialShell is now Dux Modular Shell**, at `duxlabs-dev/dux-shell`, and it runs on its own Quickshell fork, [dux-qt-base](https://github.com/duxlabs-dev/dux-qt-base), forked from upstream `9b0f339b` on 2026-11-06 with about 17 upstream PRs cherry-picked that have not been merged yet ([UPSTREAM.md](https://github.com/duxlabs-dev/dux-qt-base/blob/0366ba142538f3b601f71676f6792314a0f42534/UPSTREAM.md)). Noctalia v4 also ran on a fork, `noctalia-qs` ([FAQ](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/getting-started/faq.mdx)), and Caelestia says Quickshell "has to be the git version, not the latest tagged version" ([README](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/README.md)). So none of the big four runs on a tagged upstream Quickshell release. A small shell that uses only the core services can, but that is a decision to make on purpose.

## The patterns they converge on

1. **One shell process owns every surface, driven by IPC that the compositor's keybinds call.** The bar, launcher, notifications, OSD, lock and idle all live in one process. Keybinds call into it with `qs ipc call …`, a wrapper CLI, or Hyprland global shortcuts. Caelestia uses `caelestia shell …` and global shortcuts ([README](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/README.md)). DMS uses `dms ipc call …` ([README](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/README.md)). end-4 uses 29 `IpcHandler` files and `GlobalShortcut` (grep of `dots/.config/quickshell/ii`). Noctalia uses `noctalia msg …` ([control center docs](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/control-center/index.mdx)).
2. **Panels open from the bar, beside the widget that opened them.** The bar is the anchor for its own popouts, and each status icon opens its own detail. Caelestia's bar has popouts for network, bluetooth, battery, audio, tray and the active window, placed by the pointer's `y` along the vertical bar ([`modules/bar/popouts`](https://github.com/caelestia-dots/shell/tree/3605357e1e3d48346943509153c000e3facf4126/modules/bar/popouts), [BarWrapper.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/modules/bar/BarWrapper.qml)). DMS has "connected" surfaces that grow out of the bar ([ConnectedModeState.qml](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Common/ConnectedModeState.qml)). Noctalia has "attached panels" that overlap the bar by `panel_overlap` px to hide the seam ([bar docs](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/bar/index.mdx)).
3. **Quick-settings tiles have two actions: the tile toggles, and a second gesture opens a detail view in place.** DMS's control center has a `Details/` component per tile (network, bluetooth, audio in/out, brightness, DND, idle inhibitor, battery, VPN), expanded through `expandedSection` ([ControlCenter](https://github.com/duxlabs-dev/dux-shell/tree/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Modules/ControlCenter)). end-4 opens Wi-Fi, Bluetooth, audio and night-light dialogs inside the right sidebar ([SidebarRightContent.qml](https://github.com/end-4/dots-hyprland/blob/21733c3ca7f4edc20faafedea844dc96002c6f7f/dots/.config/quickshell/ii/modules/ii/sidebarRight/SidebarRightContent.qml)). Noctalia's control center opens straight to a tab given an IPC context, e.g. `panel-toggle control-center audio` ([docs](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/control-center/index.mdx)).
4. **One launcher, with modes chosen by a prefix.** end-4 has the most explicit table: `/` actions, `>` apps, `;` clipboard, `:` emoji, `=` math, `$` shell command, `?` web ([Config.qml](https://github.com/end-4/dots-hyprland/blob/21733c3ca7f4edc20faafedea844dc96002c6f7f/dots/.config/quickshell/ii/modules/common/Config.qml#L477-L491)). Caelestia uses `>` for actions (calc, scheme, wallpaper, power and session) and `@` to pick which field to search (`@c` categories, `@k` keywords …) ([README config](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/README.md), [Apps.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/modules/launcher/services/Apps.qml)). Noctalia splits _global_ providers, always searched and merged by relevance (apps, calculator), from _prefixed_ ones that take over the results; typing `/` alone lists the prefixes ([launcher docs](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/launcher/index.mdx)). DMS has sections (apps, files, clipboard, settings, commands) plus a **dmenu mode**: `dms dmenu` reads items on stdin and shows them in the launcher ([Controller.qml](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Modals/DLauncherV2/Controller.qml), [commands_dmenu.go](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/core/cmd/dms/commands_dmenu.go)). The dmenu mode is what lets rofi's script menus be replaced one at a time.
5. **The lock screen is the shell's own `WlSessionLock`, authenticated with Quickshell's PAM service.** Caelestia, DMS and end-4 all do this: each imports `WlSessionLock` and `Quickshell.Services.Pam` (grep). end-4 keeps hyprlock as a fallback (`lock.useHyprlock`, [Config.qml](https://github.com/end-4/dots-hyprland/blob/21733c3ca7f4edc20faafedea844dc96002c6f7f/dots/.config/quickshell/ii/modules/common/Config.qml#L374-L387)).
6. **Idle runs in the shell, as a list of timeouts.** Caelestia has `general.idle.timeouts`: a list of `{timeout, idleAction, returnAction}` with inhibit-when-audio and inhibit-when-charging, each one a Quickshell `IdleMonitor` ([IdleMonitors.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/daemons/IdleMonitors.qml)). DMS keeps separate AC and battery timeouts ([SettingsSpec/ConfigProfiles](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Common/settings/ConfigProfiles.js)). Noctalia has named `[idle.behavior.*]` entries with an optional pre-action dim ([idle docs](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/services/idle.mdx)). end-4 is the exception: it still ships hypridle ([hypridle.conf](https://github.com/end-4/dots-hyprland/blob/21733c3ca7f4edc20faafedea844dc96002c6f7f/dots/.config/hypr/hypridle.conf)). Lock-before-sleep always comes from logind's `PrepareForSleep`, never from `IdleMonitor`.
7. **Material You tokens generated from the wallpaper, then pushed out to other apps through templates.** DMS uses matugen plus its own `dank16` ([README](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/README.md)). Caelestia's Python CLI writes `scheme.json` and the shell reads it ([Colours.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/services/Colours.qml), [cli README](https://github.com/caelestia-dots/cli)). end-4 runs `switchwall.sh` ([scripts/colors](https://github.com/end-4/dots-hyprland/tree/21733c3ca7f4edc20faafedea844dc96002c6f7f/dots/.config/quickshell/ii/scripts/colors)). Noctalia has palettes plus templates ([theming docs](https://github.com/noctalia-dev/noctalia/tree/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/theming)). Every one of them also accepts a static palette. For this repo, that means the shell reads `lib/kanagawa-wave.nix` and ignores the wallpaper machinery.
8. **The heavy system work goes in a helper outside QML.** DMS has a Go daemon for NetworkManager, iwd and networkd, a BlueZ pairing agent, gamma, logind, clipboard and more ([core/internal/server](https://github.com/duxlabs-dev/dux-shell/tree/2cb19fb439c8b3146198a8cec3aae8cc75646938/core/internal/server)). Caelestia has a C++ QML plugin (`Caelestia.Config`, `Caelestia.Services`) plus a Python CLI ([plugin/](https://github.com/caelestia-dots/shell/tree/3605357e1e3d48346943509153c000e3facf4126/plugin)). end-4 shells out to `nmcli`, `cliphist` and `hyprsunset`. Where Quickshell has a native service they use it (Bluetooth device control, PipeWire, MPRIS, notifications, UPower, tray). Where it doesn't, or didn't when they wrote the code (networking, BlueZ agent, gamma, clipboard history), they fill the gap themselves.
9. **Motion is the main spatial cue, and only DMS and Noctalia have a real off switch.** See the table and the sections below. A related tip from Noctalia: turn off Hyprland's `layersIn`/`layersOut` for the shell's layers, because compositor layer animations "run on top of them and cause visual glitches" ([Hyprland notes](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/compositor-settings/hyprland.mdx)). That matters for a no-motion shell too: Hyprland's own layer animation is the motion you would still see.

## Comparison

|                 | Caelestia                                                                        | DMS / Dux                                                     | end-4 (ii)                                                       | Noctalia v5 (not Quickshell)        |
| --------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------- | ----------------------------------- |
| Bar orientation | Vertical, left, only option                                                      | Any edge, several bars; default top                           | Top by default; `bar.vertical` swaps in a separate VerticalBar   | Any edge; default top               |
| Panel model     | One fullscreen layer per screen, input mask; drawers come out of a screen border | Popouts and "connected" surfaces from the bar; optional frame | Separate PanelWindows, left/right sidebars                       | Attached panels overlapping the bar |
| Quick settings  | Utilities card: wifi, bt, mic, settings, game mode, DND, VPN                     | Control center, tiles with detail views                       | Right sidebar, 17 toggles, dialogs for wifi/bt/audio/night light | Control center tabs                 |
| Launcher        | Apps, `>` actions, `@` field filters, wallpapers                                 | Apps, files, clipboard, settings, commands, plugins, dmenu    | 7 prefixes incl. clipboard, math, shell, emoji, web              | Global plus prefixed providers      |
| Notifications   | Popups top-right, sidebar history, DND toggle                                    | Popups, history, DND with critical bypass                     | Popups, sidebar history, silent toggle                           | Toasts, history                     |
| OSD             | Right edge, vertically centred                                                   | Configurable position, per output                             | Under the bar, horizontally centred                              | Overlays (position not checked)     |
| Lock            | WlSessionLock + PAM, fprint, Howdy                                               | WlSessionLock + PAM, fprint, U2F, logind lockedHint           | WlSessionLock, or hyprlock if configured                         | Own ext-session-lock                |
| Idle            | IdleMonitor list                                                                 | IdleMonitor, AC/battery split                                 | hypridle                                                         | Native, named behaviours            |
| Night light     | None found in the shell                                                          | Go daemon, wlr-gamma-control                                  | hyprsunset (killed and relaunched)                               | wlr-gamma-control                   |
| Theming         | Material You via CLI `scheme.json`                                               | matugen + dank16                                              | matugen via `switchwall.sh`                                      | Palettes + templates                |
| Motion off      | Only a duration `scale`                                                          | `motionDuration = -1` plus `reduceMotion`                     | No global switch found                                           | `[shell.animation] enabled`         |
| Config          | `~/.config/caelestia/shell.json`, per-monitor overrides, Nexus GUI               | JSON under `~/.config/dms/`, full settings GUI                | `~/.config/illogical-impulse/config.json`, settings app          | TOML, hot reload, GUI overrides     |
| Nix             | Flake, HM module                                                                 | Flake, HM + NixOS modules, VM tests                           | Partial HM installer, not NixOS                                  | Flake (not read)                    |

## Caelestia

[caelestia-dots/shell](https://github.com/caelestia-dots/shell/tree/3605357e1e3d48346943509153c000e3facf4126), 13.5k stars, "A fluid, morphing shell for your Linux desktop". Hyprland-only.

- **Bar.** Vertical, on the left, and that is the only layout. The bar's width is its thickness, and popouts are found by `y` ([BarWrapper.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/modules/bar/BarWrapper.qml)). Default entries, top to bottom: logo, workspaces, spacer, active window, spacer, tray, clock, status icons (lock status, network, bluetooth, battery; audio, mic and keyboard layout are off by default), power ([README example config](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/README.md)). Scrolling on the bar changes workspace, volume or brightness. Requests for other positions have been closed as duplicates; a contributor wrote that it "isn't as simple as you'd think with how everything is currently built" ([#1749](https://github.com/caelestia-dots/shell/issues/1749)). The open tracker is [#1858](https://github.com/caelestia-dots/shell/issues/1858). This is the closest existing design to the one being planned here.
- **Panels.** Each screen gets one fullscreen content window whose `mask` is a set of `Region`s, so only the visible drawers take input ([ContentWindow.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/modules/drawers/ContentWindow.qml)). The drawers are laid out around a screen border: OSD and session menu on the right edge, vertically centred; notifications top-right; launcher bottom-centre; dashboard top-centre; utilities bottom-right; sidebar down the right ([Panels.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/modules/drawers/Panels.qml)). Many of them open on hover or on a drag past a threshold (`showOnHover`, `dragThreshold`), and the "morphing" is the border growing into the drawer. That is pure motion. Without the animation it becomes rectangles appearing at screen edges, which is a coherent design but not this one.
- **Quick settings.** A utilities card with wifi, bluetooth, mic, settings, game mode, DND and VPN ([README](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/README.md)). The details live in the bar popouts, not in the toggles. _Game mode_ is a list of Hyprland keywords to set (animations, blur, gaps off), which is a neat way to express a mode.
- **Launcher.** Apps, with optional fuzzy matching. `>` runs actions: Calculator (via qalc), Scheme, Wallpaper, Variant, Random, Light/Dark, Shutdown/Reboot/Logout/Lock/Sleep, Settings. `enableDangerousActions` defaults to false. `@` prefixes pick the field to search (`@i` id, `@c` categories, `@d` comment, `@e` exec, `@w` WM class, `@g` generic name, `@k` keywords) ([Apps.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/modules/launcher/services/Apps.qml)). Clipboard and files are not in the launcher.
- **Notifications.** Popups, grouped history in the sidebar, DND as a quick toggle, separate expire timeouts for fullscreen.
- **Lock and idle.** `WlSessionLock` + PAM, with fingerprint and Howdy face auth. Idle is a `Variants` of `IdleMonitor`s, one per configured timeout. A C++ `SessionManager` handles logind `aboutToSleep`, used for `lockBeforeSleep` ([IdleMonitors.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/daemons/IdleMonitors.qml)). The companion dots set Hyprland's `allow_session_lock_restore = true` ([misc.lua](https://github.com/caelestia-dots/caelestia/blob/66125ba4c71072fe1a290f40c9656b7917b7a8c9/hypr/hyprland/misc.lua)). I found no code that re-locks after a restart.
- **Night light.** No gamma, sunset or temperature code in the shell repo (grep). Not verified whether the CLI provides one.
- **Motion.** Every animation goes through `Anim`, which takes its duration from tokens ([Anim.qml](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/components/Anim.qml)). There is a global `appearance.anim.durations.scale` ([appearanceconfig.hpp](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/plugin/src/Caelestia/Config/appearanceconfig.hpp#L222-L225)), but no documented off switch, and I didn't test `scale: 0`. The pattern worth borrowing even without motion: one component, so one place where durations are decided.
- **Packaging and config.** Flake with `packages.with-cli` and `homeManagerModules.default` (`settings`, `extraConfig`, systemd, CLI) ([flake.nix](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/flake.nix), [hm-module.nix](https://github.com/caelestia-dots/shell/blob/3605357e1e3d48346943509153c000e3facf4126/nix/hm-module.nix)). The flake pins Quickshell git. Config is a sparse `~/.config/caelestia/shell.json` (you write only what you change), with per-monitor overrides under `monitors/<name>/shell.json`. A settings GUI called _Nexus_ has been added (`modules/nexus`). Needs a compiled C++ plugin and fonts. Usable outside the authors' dots, but it is Hyprland-specific.

## DMS (Dux Modular Shell)

[duxlabs-dev/dux-shell](https://github.com/duxlabs-dev/dux-shell/tree/2cb19fb439c8b3146198a8cec3aae8cc75646938), 9.2k stars. It "replaces waybar, swaylock, swayidle, mako, fuzzel, polkit, and everything else" across niri, Hyprland, Sway, Mango, labwc, Scroll and Miracle ([README](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/README.md)). The most engineered of the four, and the one whose _process_ (tests, lint, VM checks) is most worth copying.

- **Bar.** `barConfigs` is a list, so you can have several bars, each with a `position` from `Top, Bottom, Left, Right, TopCenter, BottomCenter …` ([SettingsData.qml](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Common/SettingsData.qml#L30-L36)). The default is one top bar with left, centre and right widget lists ([SettingsSpec.js](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Common/settings/SettingsSpec.js#L1771-L1782)). Vertical support is built on an `AxisContext` object (`isVertical`, `primarySize`, `crossSize`, `setPrimaryPos`), so one bar implementation serves every edge ([AxisContext.qml](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Modules/DBar/AxisContext.qml)). end-4 instead keeps a second, separate VerticalBar. If you only ever have a vertical bar you need neither, but the axis object is the cheap way to keep the option open.
- **Panels.** Popouts from bar widgets, plus a "connected" mode where the popout looks like part of the bar, and an optional screen frame. A density preset and an interface style are global settings.
- **Control center.** Tiles (network, bluetooth, audio devices, brightness, battery, DND, idle inhibit, night mode, dark mode, VPN, color picker, disk, running apps), each with a `Details/` view that opens in place ([ControlCenter](https://github.com/duxlabs-dev/dux-shell/tree/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Modules/ControlCenter)). A Wi-Fi password modal, a BlueZ pairing modal and a polkit auth modal are separate surfaces.
- **Launcher.** Sections for pinned, apps, settings, clipboard, files (via `dsearch`), plugins and commands. The `dmenu` mode is the important one for replacing rofi scripts.
- **Notifications.** History, DND with `notificationDndAllowCritical`, DND while screen sharing, per-app timed mutes, configurable popup position ([SettingsSpec.js](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Common/settings/SettingsSpec.js#L1581-L1590)).
- **OSD.** `osdPosition`, with per-output overrides and a toggle per kind (volume, brightness, mic, caps lock, power profile, DND …).
- **Lock.** `WlSessionLock` + PAM, fingerprint, U2F, optional logind integration. On startup, if logind says the session is locked (`locked` or `lockedHint`), the restarted shell re-locks itself ([Lock.qml](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Modules/Lock/Lock.qml#L76-L88)). This is the only crash-recovery logic I found in any shell. It still needs the compositor to accept a new lock client; I found no `allow_session_lock_restore` in DMS's generated Hyprland config, so on Hyprland that setting is up to you. An open bug shows the failure case: the lock crash-loops when monitors power off on lock ([#4103](https://github.com/duxlabs-dev/dux-shell/issues/4103)).
- **Idle.** `IdleMonitor` and `IdleInhibitor`, AC/battery timeouts, fade-to-lock and fade-to-DPMS grace periods, lock before suspend.
- **Night light.** Its own Go daemon speaking `wlr-gamma-control` directly, with a sun calculator ([server/wayland](https://github.com/duxlabs-dev/dux-shell/tree/2cb19fb439c8b3146198a8cec3aae8cc75646938/core/internal/server/wayland)). No hyprsunset.
- **Motion.** Every duration is `motionMs(spec) = spec * motionScale`. `motionDuration = -1` sets `motionOff`, which makes the scale 0 and forces `reduceMotion` ([Theme.qml](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Common/Theme.qml#L1004-L1019), [SettingsStore.js](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/Common/settings/SettingsStore.js)). There is a `settings-animation-duration` test. This is the cleanest "motion is a token, and the token can be zero" design in the survey.
- **Helpers.** The `dms` Go binary is CLI, IPC socket and backend at once: NetworkManager, iwd and networkd backends with their own secret agents; a BlueZ agent; brightness; clipboard; CUPS; logind; Tailscale; weather; system updates ([server/](https://github.com/duxlabs-dev/dux-shell/tree/2cb19fb439c8b3146198a8cec3aae8cc75646938/core/internal/server)). ## Noctalia (v5, native C++)

[noctalia-dev/noctalia](https://github.com/noctalia-dev/noctalia/tree/54958562e9f8a83aaa07eba7c0ff353ba45b1167), 12.3k stars. Included for its design and its docs, which are the clearest of the four. It is not a Quickshell codebase.

- **Scope as policy.** [SCOPE.md](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/SCOPE.md) judges every request with four questions: _Does it need the shell core? Does it extend something that exists? Does it fit the existing stack? Who maintains it in a year?_ It also rejects "feature parity with another shell as the motivation". This is the most transferable thing in the survey for a small shell.
- **Bar.** `position = top|bottom|left|right`; `thickness` is "height for horizontal, width for vertical"; per-monitor overrides of every field; right-click on empty bar opens the control center ([bar docs](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/bar/index.mdx)).
- **Launcher.** The global versus prefixed provider split (pattern 4), with plugin providers that can "drill in" by rewriting the query and keeping the launcher open ([plugin entries](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/plugins/development/entries.mdx)). The drill-in is the clean model for nested menus like network → SSID → password.
- **Night light.** `wlr-gamma-control`; the schedule fades over an hour, anchored to the wall clock, but "Anything else applies at once", meaning toggles snap ([night-light docs](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/services/night-light.mdx)). A good rule for a no-motion shell: animate only what the system does slowly, never what the user does.
- **Idle.** Named behaviours with an order, native actions, optional pre-action dim that cancels on input ([idle docs](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/docs/user/services/idle.mdx)).
- **Motion.** `[shell.animation] enabled`/`speed` ([example.toml](https://github.com/noctalia-dev/noctalia/blob/54958562e9f8a83aaa07eba7c0ff353ba45b1167/example.toml)); plus the advice to disable the compositor's layer animations (pattern 9).
- **Lock crash, as a real case.** On v4, a lock created under VRAM exhaustion aborted the process, which left Hyprland's "lockscreen app died" screen, and every automatic restart crashed the same way ([#3498](https://github.com/noctalia-dev/noctalia/issues/3498)). This is what you get when the lock lives in the same process as everything else.

**WlSessionLock crash semantics.** From the type's own docs: "If the WlSessionLock is destroyed or quickshell exits without setting `locked` to false, conformant compositors will leave the screen locked and painted with a solid color… The lock dying will not expose your session, but it will render it inoperable" ([session_lock.hpp](https://github.com/quickshell-mirror/quickshell/blob/9b0f339b19057f4731bf3b48293307d7ef241671/src/wayland/session_lock.hpp#L48-L53)). A hot reload keeps the lock: the new generation takes over the old `SessionLockManager` ([session_lock.cpp](https://github.com/quickshell-mirror/quickshell/blob/9b0f339b19057f4731bf3b48293307d7ef241671/src/wayland/session_lock.cpp#L34-L43)). On Hyprland, `misc:allow_session_lock_restore` (default `false`) "will allow you to restart a lock screen app in case it crashes", and `lockdead_screen_delay` controls the fallback screen ([Hyprland wiki](https://github.com/hyprwm/hyprland-wiki/blob/bd104c02d476c726d665e4ee14e861b97c21b67d/content/configuring/core/config-options.md)). So recovering from a crash takes three things: that Hyprland option, something that restarts the shell (systemd `Restart=on-failure`; the home-manager module sets this), and a shell that re-locks on start when logind says the session is locked (DMS's pattern). If the crash is deterministic, as in Noctalia #3498, a restart loops, which is the argument for an independent fallback locker (end-4's hyprlock pattern) or a lock that runs as its own `qs` instance. The separate-instance idea is my inference; none of the surveyed shells does it.

**Packaging.** nixpkgs `quickshell` 0.3.2 builds with `INSTALL_QML_PREFIX`, so `.qmltypes` files are installed under `lib/qt-6/qml/Quickshell` ([package.nix](https://github.com/NixOS/nixpkgs/blob/b1b875982b17dabde9b4a37f3e229e74913e6db3/pkgs/by-name/qu/quickshell/package.nix)). Upstream also ships a flake ([flake.nix](https://github.com/quickshell-mirror/quickshell/blob/9b0f339b19057f4731bf3b48293307d7ef241671/flake.nix)). home-manager has `programs.quickshell`, with `enable`, `package`, `configs` (an attrset of name → path, deployed to `~/.config/quickshell/<name>`), `activeConfig`, and `systemd.enable`/`target` (a user service with `Restart=on-failure`) (`modules/programs/quickshell.nix` in the home-manager revision this repo locks, `3b8140d2`). Because the 0.3.0 shell-id change derives ids from the symlink path, deploying through `xdg.configFile` symlinks is now stable across rebuilds.

## Validation at build time

What I verified by running nixpkgs `quickshell` 0.3.2 and `qtdeclarative` 6.12.0 against throwaway configs (my own test, 2026-11-27):

- **There is no check mode.** `qs` has no validate, dry-run or check subcommand ([parsecommand.cpp](https://github.com/quickshell-mirror/quickshell/blob/9b0f339b19057f4731bf3b48293307d7ef241671/src/launch/parsecommand.cpp)).
- **If the first load fails, the process exits.** `RootWrapper` calls `exit(-1)` when there is no generation after the first load ([rootwrapper.cpp](https://github.com/quickshell-mirror/quickshell/blob/9b0f339b19057f4731bf3b48293307d7ef241671/src/core/rootwrapper.cpp#L43-L47)). Observed: exit 255 for a syntax error (`Expected token '}'`), an unknown property (`Cannot assign to non-existent property`) and a missing `qs.*` module (`module "qs.nope" is not installed`). A valid config logs `Configuration Loaded` and keeps running, so a check has to wrap it in `timeout` and treat exit 124 plus that log line as a pass.
- **Runtime binding errors do not fail the load.** A `ReferenceError` in a binding is logged as a `WARN scene:` line, and then `Configuration Loaded` is printed anyway. A check must therefore also fail on `WARN scene` / `ReferenceError` / `TypeError` lines in the log.
- **`QT_QPA_PLATFORM=offscreen` does not work** for a real shell: the first `PanelWindow` fails with `No PanelWindow backend loaded`, exit 255. You need a Wayland compositor. **A headless sway works**: `WLR_BACKENDS=headless WLR_RENDERER=pixman sway`, then `qs -p …` with `QT_QPA_PLATFORM=wayland` loaded a config with `PanelWindow`, `WlSessionLock` and `IdleMonitor`, and correctly reported the three failing configs. One gotcha: `XDG_RUNTIME_DIR` must be a short path, because the Wayland socket path has a ~108-byte limit. This would fit a NixOS VM test in `checks/`; headless Hyprland was not tried.
- **On a broken hot reload, the old config keeps running.** Observed: after appending garbage to a running config, the log shows `Failed to load configuration … Syntax error` and the process stays up. The code shows the reload-failed popup and keeps the old generation ([rootwrapper.cpp](https://github.com/quickshell-mirror/quickshell/blob/9b0f339b19057f4731bf3b48293307d7ef241671/src/core/rootwrapper.cpp#L104-L144)). Reloads are skipped when no file content changed (0.3.0).
- **qmllint partly works.** With `-I <qtdeclarative>/lib/qt-6/qml -I <quickshell>/lib/qt-6/qml`, it catches unknown properties (`Could not find property "notAProperty" [missing-property]`). Two problems: (1) on 0.3.2 with Qt 6.12, it falsely reports `Type PanelWindow is not creatable [uncreatable-type]`; master's changelog says "Fixed most broken qml types in qmlls/qmllint for Qt 6.12", which is not released yet ([next.md](https://github.com/quickshell-mirror/quickshell/blob/9b0f339b19057f4731bf3b48293307d7ef241671/changelog/next.md)), and the docs already say "`PanelWindow` in particular cannot be resolved" ([install-setup](https://quickshell.org/docs/v0.3.2/guide/install-setup)); (2) `qs.*` imports only resolve through the tooling VFS (symlinks plus a generated `qmldir`) that a _running_ `qs` writes when an empty `.qmlls.ini` sits next to `shell.qml` ([toolsupport.cpp](https://github.com/quickshell-mirror/quickshell/blob/9b0f339b19057f4731bf3b48293307d7ef241671/src/core/toolsupport.cpp)). That VFS goes stale when files are renamed. qmllint exits 0 on warnings unless you pass `-W 0` / `--max-warnings 0`.
- **How DMS does it.** `make lint-qml` runs qmllint with `--ignore-settings -W 0 --bare` and the VFS's import paths. The VFS is written by `dms qs tooling -p …`, a dux-qt-base command that "writes the config and module mirror without launching the shell" and does not exist upstream ([qmllint-entrypoints.sh](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/scripts/qmllint-entrypoints.sh)). On top of that it runs logic tests and `qmltestrunner` lock tests with mocks, none of which need a compositor ([tests/README.md](https://github.com/duxlabs-dev/dux-shell/blob/2cb19fb439c8b3146198a8cec3aae8cc75646938/quickshell/tests/README.md)). On upstream Quickshell, the equivalent is to start `qs` once under headless sway with `.qmlls.ini` present, then lint against the VFS it wrote.
